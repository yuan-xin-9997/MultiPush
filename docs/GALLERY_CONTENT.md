# 图文内容（以图片为主）

## 功能概览

内容库现在支持三种内容类型：

| 类型 | 入口 | 说明 |
| --- | --- | --- |
| `article` 文章 | 新建文章 | Tiptap 富文本，面向长文与常规图文平台 |
| `gallery` 图文 | 新建图文 | 图片优先：标题 + 有序图片（可带图注）+ 配文，面向公众号贴图、抖音图文、小红书 |
| `video` 视频 | 新建视频 | 视频为主，带标题和正文，支持系统内时间线剪辑与成片导出 |

`gallery` 工作台的目标不是替代富文本编辑器，而是把「图片顺序、封面、图注、配文」四件事放在一个页面里，减少在公众号贴图、抖音图文和小红书之间反复整理图片的成本。

## 页面入口

- 内容库右上角「新建图文」，或空状态页「新建图文」；
- 内容库中的图文内容带紫色「图文」角标，底部显示「N 张图」；普通文章使用绿色「文章」角标，视频使用红色「视频」角标；
- 点击卡片进入 `/gallery/:id` 全屏工作台；
- 误入 `/editor/:id` 的图文内容会自动跳转到图文工作台，误入图文工作台的视频/文章也会跳回对应工作台。

## 图文工作台

```
┌──────────────────────────────────────────────────┐
│ ← 内容库  [图文]  保存状态         收藏  渲染  更多 │
├───────────────────────────────┬──────────────────┤
│ 标题（大号输入）                │ 封面预览          │
│ 图片网格：拖拽 / 箭头排序、图注   │ 标签、状态         │
│ 配文（纯文本，多行）             │ 平台图片上限与提醒  │
│                               │ 删除图文          │
└───────────────────────────────┴──────────────────┘
```

- **添加图片**：点击「添加图片」或把图片拖进图片区域；也可点「从素材库添加」选择已有图片。支持 JPG / PNG / WebP / GIF，单张 ≤20 MB，最多 35 张（取三个目标平台中最高的抖音上限）。
- **排序**：图片卡片左下角拖动手柄可拖动排序；也可使用 ↑ / ↓ 箭头。触屏设备会常显图片工具栏。
- **封面**：默认使用第一张图片；点击任意图片上的星标即可设为封面。删除封面图时自动回退到新的第一张。
- **图注**：每张图片下方可填写一行说明，保存为 `figure > figcaption`；发布到公众号/知乎/博客等长文平台时会显示为图片说明。
- **配文**：纯文本多行输入，每行保存为一段；作为小红书文案、抖音文案和公众号贴图纯文本正文。标题和配文合计会实时显示字数。
- **发布信息**：标签（逗号分隔，最多 10 个）、草稿/待发布状态、收藏。
- **自动保存**：停止输入约 0.8 秒后在后台保存；`Ctrl/Cmd + S` 立即保存；关闭页面前提示未保存。
- **更多菜单**：复制图文、导出 Markdown / HTML / MultiPush JSON、删除（进入回收站）。
- **渲染**：保存后进入渲染工作台，可直接生成公众号贴图、小红书卡片、抖音竖图文的预览与素材。

## 数据模型

图文内容沿用现有内容表，不新增表：

- `contents.kind = 'gallery'`；
- `contentJson` 是标准 Tiptap 文档：图片保存为 `figure`（`image` + 可选 `figcaption`）节点，配文保存为 `paragraph` 节点，按「全部图片 → 配文段落」的顺序排列；
- `contentHtml` 由同一份数据生成，图片输出为 `figure/figcaption`，配文输出为 `<p>`；渲染器、发布服务、导出、批量任务都直接复用现有 HTML 管线；
- 封面保存 `coverImage`；`imageCount` 由后端统计 HTML 中的 `img` 数量；
- 保存时同时写 `contentJson` 与 `contentHtml`，二者内容哈希一致，不会触发 `contentJsonStale`。

### 兼容与迁移

- SQLite 旧库的 `contents.kind` 带有 `CHECK (kind IN ('article', 'video'))`。启动时会自动重建该表并加入 `gallery`，保留全部行、索引和子表外键；迁移后执行 `PRAGMA foreign_key_check`。
- 历史 `article` / `video` 数据不变；旧数据库中没有 `kind` 列时仍按原有增量迁移补列。
- MultiPush JSON 导出包含 `kind: "gallery"`；重新导入时保留图文中类型。视频时间线不在内容 JSON 中，视频导出仍按原有规则导入为文章。

## 平台适配

| 平台 | 图片上限 | 图文工作台对应输出 |
| --- | --- | --- |
| 微信公众号贴图 | 20 张 | 按图片顺序取前 20 张 + 标题（≤32 字）+ 纯文本配文 |
| 小红书 | 18 张 | 3:4 卡片，首图作为封面卡，图片按顺序进入卡片与 ZIP 素材 |
| 抖音图文 | 35 张 | 竖屏图文预览、标题 + 配文 + 话题、图片素材清单 |

图片数量超过目标平台上限时，工作台会显示提醒；渲染器也会按平台规则截取并给出警告。

## AI 创作

`create_content` 的 `kind` 支持 `gallery`。AI 可以用 `mediaIds` 按顺序把已上传图片插入图文，并把第一张作为封面；也可以用 `update_content` 给已有图文追加图片。图文内容会出现在 `list_contents(kind="gallery")` 的结果中。

## 验证

- `npm run typecheck`、`npm test`、`npm run build` 通过。
- 服务端新增数据库迁移测试：从旧 `CHECK` 约束升级后旧内容保留、子表行保留、可创建并筛选 `gallery`。
- Playwright 端到端：从内容库新建图文 → 上传 3 张图片 → 填写标题/图注/配文 → 调序 → 自动保存 → 刷新恢复 → 内容库显示「图文」角标和「3 张图」→ 重新打开 → 渲染公众号贴图/小红书/抖音/公众号均识别 3 张图片；1440×980 与 390×844 无横向溢出。
