# 注册邀请码与管理员

## 规则

- 生产环境注册必须填写有效邀请码。
- 邀请码只能由管理员在「设置 → 邀请码」生成。
- 每个邀请码可设置 1–1000 次使用次数，以及可选的失效时间。
- 管理员可以停用/重新启用邀请码；停用后不能继续注册，已注册账号不受影响。
- 邀请码消耗和创建用户在同一个 SQLite 事务中完成；用户名/邮箱冲突会回滚使用次数。

## 管理员

- 数据库迁移会将既有 `yuanxin` 账号标记为管理员。
- 普通用户不会看到「邀请码」设置 Tab，直接访问管理员接口返回 403。
- 管理员判断使用 `users.is_admin`，不依赖客户端状态。

## 测试/验收绕过

注册策略由服务端配置决定：

- `NODE_ENV=test`：自动绕过；
- 开发环境（`NODE_ENV=development`，例如 `npm run dev`）：自动绕过；
- 生产验收可显式设置 `INVITE_CODE_BYPASS=1`，但不要写入生产 `.env`；
- Jenkins 只在构建/测试进程设置该变量，systemd 生产服务不继承，因此线上注册仍要求邀请码。

## 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/auth/registration-config` | 公开 | 当前是否需要邀请码 |
| GET | `/api/admin/invite-codes` | 管理员 | 邀请码列表 |
| POST | `/api/admin/invite-codes` | 管理员 | 生成邀请码，body: `maxUses`、可选 `expiresAt` |
| PATCH | `/api/admin/invite-codes/:id` | 管理员 | body: `active` |

## 验证

1. 使用管理员 `yuanxin` 登录，打开「设置 → 邀请码」。
2. 生成一个 `maxUses = 1`、失效时间为未来的邀请码。
3. 退出后用该邀请码注册一个新账号；再次使用同一邀请码应提示「邀请码使用次数已用完」。
4. 用普通账号打开设置，确认没有邀请码 Tab；直接请求管理员接口应返回 403。
