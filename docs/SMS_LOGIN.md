# 平台手机验证码登录

## 已支持范围

| 平台 | 登录页手机验证码 | 说明 |
| --- | --- | --- |
| 知乎 | ✅ | 登录页默认「验证码登录」，可能触发 NECaptcha 滑块 |
| 微博 | ✅ | 使用 `passport.weibo.com` 登录页的「验证码登录」 |
| 今日头条 | ✅ | 登录页「验证码登录」 |
| 百家号 | ✅ | 百度通行证「短信快捷登录」 |
| 豆瓣 | ✅ | 「短信登录／注册」 |
| 掘金 | ✅ | 默认手机验证码登录 |
| 抖音 | ✅ | 创作者中心「验证码登录」 |

未加入：

- 微信公众号：登录页没有手机验证码，只有扫码和账号密码；账号密码登录通常仍需要管理员微信安全验证。
- 小红书：自动登录与发布已停用，因此不重新启用登录入口。
- 简书、少数派：登录页没有手机验证码，当前分别使用 Cookie / 微信扫码。
- 个人博客：使用 Halo 令牌连接。

## 工作方式

1. 用户在发布页点击「手机验证码登录」，输入 11 位中国大陆手机号并勾选同意平台协议。
2. 服务端启动一个隔离的 Chromium 上下文，打开平台官方登录页，切换到短信登录，填写手机号并点击「发送验证码」。
3. 平台发送短信后，用户把验证码填回 MultiPush；服务端在同一浏览器上下文里填写并提交。
4. 登录成功后读取 `storageState`，由对应平台服务调用现有的 `checkSession` 校验账号，再按原有加密方式保存。
5. 任何一步遇到滑块、安全验证、验证码错误或超时，都会停止并提示改用扫码；不会尝试绕过验证。

## 安全约束

- 不保存平台密码；本功能完全不接收密码。
- 完整手机号和验证码不写入数据库、不写入日志、不在 API 响应中返回；响应只包含脱敏手机号。
- 验证码尝试 5 分钟过期；同一用户同时最多一个短信登录请求；同一用户、平台和手机号 20 秒内不能重复发送。
- 复用各平台原来的会话加密密钥和数据库字段，没有新增数据库表。
- 关闭弹窗或离开页面会取消服务端浏览器上下文；服务停止时统一关闭。
- 平台登录状态仍按用户隔离；导入会话前会调用原平台的 `checkSession`，不会仅凭页面跳转就断言登录成功。

## API

需要登录（Bearer Token）：

```http
POST /api/platform-sms/:platform/start
Content-Type: application/json

{ "phone": "13800138000" }
```

```http
POST /api/platform-sms/:platform/:id/verify
Content-Type: application/json

{ "code": "123456" }
```

```http
DELETE /api/platform-sms/:platform/:id
```

`:platform` 取值：`zhihu`、`weibo`、`toutiao`、`baijiahao`、`douban`、`juejin`、`douyin`。

## 验证

```bash
# 真实登录页选择器检查：只填手机号，不点击发送，不会产生短信
npm run smoke:sms-login-selectors

# 构建后检查 7 个发布页的弹窗、手机号校验和协议勾选
npm run smoke:sms-login
```

单元测试：`server/test/sms-login.test.ts`。

真实短信发送与平台登录需要用户自己的手机号；当前环境不能代替用户接收验证码，因此上线后需至少用每个平台各测试一次。遇到平台改版或风控时，页面会提示改用扫码，不应尝试绕过。

## 回滚

- `git revert` 本次提交后重新构建；没有数据库迁移。
- 已保存的登录会话与原有扫码登录完全兼容，回滚不会影响已有账号状态。
