# 视频内容与系统内剪辑

## 功能概览

MultiPush 的内容分为三种类型：

| 类型 | 说明 |
| --- | --- |
| `article` 文章 | Tiptap 富文本正文，面向长文与常规图文平台排版 |
| `gallery` 图文 | 图片优先：标题 + 有序图片（可带图注）+ 配文，面向公众号贴图、抖音图文和小红书；见 [图文内容说明](GALLERY_CONTENT.md) |
| `video` 视频内容 | 视频为主，带标题和正文文案，支持上传一段或多段视频并在系统内剪辑 |

视频内容支持：

- **多段上传**：新建视频内容时可一次选择多个视频文件（MP4 / WebM / MOV，单段最大 200MB），上传后按顺序进入剪辑时间线；
- **时间线剪辑**：对同一条视频内容内的素材进行修剪（入点 / 出点）、调序、删除、追加，时间线自动保存；
- **成片导出**：服务端使用 ffmpeg 按时间线逐段剪辑、统一规格后合并成片，成片自动存入素材库；
- **渲染记录预览**：智能渲染自动把最近导出的成片嵌入渲染结果（公众号内嵌播放器、抖音/小红书视频笔记预览）；
- **AI 操控剪辑**：AI 创作可通过工具查看时间线、修剪/调序/增删片段并触发导出，见 [AI 创作说明](AI_CREATION.md)。

## 剪辑实现方案（开源成熟方案）

剪辑引擎使用 **FFmpeg**（开源视频处理事实标准，与主流云端剪辑产品同源）：

- 服务端 `ffprobe` 读取每个素材的时长、分辨率、是否有音轨；
- 每个片段按时间线单独执行 `ffmpeg -ss/-to` 裁剪，并统一规格：H.264 + AAC、30fps、`yuv420p`、偶数尺寸、缺失音轨用静音填充（`anullsrc`），保证不同来源（手机竖拍、横拍、WebM 录屏）的片段可以无损衔接；
- 多片段通过 ffmpeg `concat` demuxer 合并（规范化后 `-c copy`），输出 `+faststart` MP4；
- 导出是异步任务：返回 `exportId`，支持轮询进度（解析 ffmpeg `-progress`），服务重启后任务标记失败并提示重新导出；同一时间只跑一个导出任务。

前端工作台为类剪映/CapCut 的时间线交互：预览播放器 + 片段列表 + 时间线总览条，支持「设入点 / 设出点」（以当前播放位置为准）与逐段播放 / 整条播放预览。剪辑计算在服务端完成，浏览器只做预览，不依赖 ffmpeg.wasm（性能差）或特定浏览器能力（WebCodecs 兼容性受限）。

## 页面入口

- 内容库右上角「新建视频」，或空状态页「新建视频」；视频工作台也可「从素材库添加视频」复用已有素材；
- 内容库中视频内容带红色「视频」角标（普通文章为绿色「文章」，图文为紫色「图文」），点击直接进入 `/video/:id` 视频工作台；
- 文章编辑器保持不变；误入 `/editor/:id` 的视频和图文内容会自动跳转到对应工作台。

## 视频工作台

```
┌──────────────────────────────────────────────────┐
│ ← 内容库  [标题]           保存状态  导出记录 导出成片 │
├─────────────────────────────┬────────────────────┤
│ 预览播放器（逐段/整条播放）      │ 上传视频片段（多选）    │
│ 上一段/播放/设入点/设出点/下一段 │ 上传进度              │
│ 时间线总览条（按时长比例）      │ 片段列表              │
│ 正文内容（多行文本，自动分段）   │  · 缩略图 + 入/出点    │
│ 标签                         │  · 上移/下移/删除      │
└─────────────────────────────┴────────────────────┘
```

- 标题、正文、标签与时间线都会自动保存（Ctrl/Cmd+S 可手动保存）；
- 正文按空行分段存储为 HTML 段落，会作为内容摘要与字数来源；
- 时间线自动保存失败时页面提示，可重试；关闭页面前有未保存提醒；
- 删除片段只从时间线移除，不会删除素材库中的原视频；
- 复制视频内容会连同时间线一起复制（引用同一批素材）。

## 导出成片

- 「导出成片」使用当前已保存（或待保存时先强制保存）的时间线创建异步任务；
- 导出记录面板显示排队中 / 导出中（含进度百分比）/ 已完成 / 失败；
- 完成后可直接预览和下载成片；成片同时作为新的视频素材存入素材库，可在抖音发布时选择（视频笔记），或在 AI 创作中用 `videoMediaId` 发布；
- 总时长上限 2 小时；导出过程超时（45 分钟）自动失败；
- 服务器未安装 ffmpeg 时：剪辑时间线不受影响，导出按钮会得到明确提示（页面顶部也会显示能力提示横幅）。

## 渲染记录预览成片

智能渲染会把视频内容**最近一次导出成功的成片**作为正文开头的视频插入渲染结果：

- 公众号 / 知乎 / 少数派 / 博客等长文平台：正文顶部出现内嵌视频播放器（原生 `<video controls>`，与图片同源绝对地址），渲染工作台手机壳预览可直接播放；
- 抖音：自动按「视频笔记」竖屏预览，文案不含视频地址；
- 小红书：自动切到「视频笔记」预览模式，并提供成片下载；
- 微博 / 头条 / 百家号 / 豆瓣 / 掘金 / CSDN / 简书等不支持视频的平台：保持原有提示「正文中的视频会在发布时忽略/移除」，成片仍可通过素材库手动上传。

规则：

- 只使用**已导出完成**的成片；没有导出过成片时，渲染结果与普通图文一致（无视频）；
- 渲染记录保存的是生成时刻的成片快照；重新导出后再次「生成渲染」即可获得新成片的渲染；
- 该注入只发生在渲染快照里，不会修改视频内容的正文本身；
- AI 创作与批量渲染 / 批量发布走同一管线，行为一致。

## API 契约（供自动化与 AI 调用）

所有接口沿用登录鉴权（`Authorization: Bearer <token>`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/contents` | 创建内容；`kind: "video"` 创建视频内容 |
| GET | `/api/contents?kind=video` | 按类型筛选内容列表 |
| GET | `/api/contents/:id/video` | 读取剪辑时间线（片段含素材信息）与服务器 ffmpeg 能力 |
| PUT | `/api/contents/:id/video/timeline` | 整体替换时间线 `{"clips":[{"mediaId","trimStart","trimEnd","duration"}]}`，顺序即成片顺序 |
| POST | `/api/contents/:id/video/export` | 创建导出任务，返回 `{ export }` |
| GET | `/api/contents/:id/video/exports` | 列出该内容的导出任务 |
| GET | `/api/video-exports/:exportId` | 查询导出任务状态 / 进度 / 输出素材 |
| DELETE | `/api/video-exports/:exportId` | 删除导出记录 |
| GET | `/api/media/:id/probe` | ffprobe 探测视频素材（时长 / 分辨率 / 音轨） |

时间线片段字段：`trimStart`（秒）、`trimEnd`（秒；`null` 表示保留到素材结尾）、`duration`（素材总时长，秒）。服务端会按素材时长裁剪非法值；`trimEnd` 接近素材结尾时自动归一为 `null`。

## 数据与存储

- `contents.kind`：`article` / `gallery` / `video`（默认 `article`，历史数据自动迁移，旧 `CHECK` 约束自动升级）；
- `video_projects`：每条视频内容一行 `timeline_json`（有序片段列表），保存时同步更新 `contents.video_count`；
- `video_exports`：导出任务（状态、进度、时间线快照、输出素材 ID）；
- `media.meta_json`：上传视频时 ffprobe 的元数据（时长、宽高、编码、是否有音轨）；
- 导出过程文件位于 `DATA_DIR/video-exports/<exportId>/`，任务结束（成功或失败）自动清理；成片复制进 `DATA_DIR/uploads/` 并登记为素材。

## 部署要求

- 服务器安装 `ffmpeg` / `ffprobe`（部署服务器 Ubuntu 24.04 已预装 ffmpeg 6.1.1），或通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定绝对路径；
- 本地桌面版（Electron）未内置 ffmpeg：剪辑可正常保存，导出需要本机安装 ffmpeg 并保证在 PATH 中（或设置环境变量）；
- 数据库迁移为增量式：旧库首次启动会自动补齐 `contents.kind`、`media.meta_json` 与两张新表，历史内容默认为图文类型，无破坏性变更。
