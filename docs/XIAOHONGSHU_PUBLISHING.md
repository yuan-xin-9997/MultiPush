# 小红书图文发布

入口：发布管理 → 小红书，或在渲染工作台选择「发布到小红书」。

## 使用

1. 先保存小红书排版。当前版本支持图文；视频笔记暂不支持直接发布。
2. 点击「扫码连接小红书」，用小红书 App 扫描官方二维码并确认。
3. 选择排版。默认等待字体加载完成，按实际文字高度自动分页，再按预览顺序把卡片转换为 1080×1440 PNG；也可一次选择 1–18 张图片替换，按选择顺序上传，每张不超过 10 MB。
4. 检查标题、文案、图片，点击正式发布并确认。标题限制 20 字。正文、分隔符与文本话题合计限制 1000 字，发布页会自动为话题预留空间、精简超长正文，并尽量在句末加省略号；话题异常多时会优先保留正文、减少部分话题。预览显示实际提交文案和字数，并提示精简情况。原文与保存的文案不改写。
发布页先按实际文字高度分页。若超过 18 张，会保留首尾卡片，并沿全文等距选取片段，精简为 18 张后按原顺序发布；预览会显示选中卡片和省略数量。此方式是片段精选，不是生成式摘要，可能省略细节或图片；请在发布前检查预览。原文、已保存的完整卡片以及笔记文案不变，不要求全文进入发布图片。无法自动容纳的超长标题仍需在渲染工作台调整。

5. 查看发布记录。平台明确返回成功和笔记编号后，才标记成功；这表示提交成功，最终展示仍以小红书审核为准。

文案来自排版的正文和话题，由前后端共用同一整理规则。短文保持不变，超长文案采用开头节选，不是生成式摘要；发布前请检查预览。话题当前作为 `#话题` 文本填写，未实现官方话题候选词绑定。

## 登录与部署

使用项目现有的 `playwright-core`，无需安装额外 MCP 服务。服务器需要 Chrome / Chromium；自动查找失败时设置 `XHS_BROWSER_PATH`，也支持已有 `WECHAT_BROWSER_PATH` / `CHROME_BIN`。

会话按 MultiPush 用户隔离，使用 AES-256-GCM 加密后存入 SQLite，以用户 ID 绑定密文。密钥位于 `DATA_DIR/.xiaohongshu-session-key`。应一起备份数据库与该密钥；密钥丢失或登录过期后需重新扫码。断开连接会删除系统保存的会话，不会删除远端笔记。

## 编辑器内容核对

填写后按编辑器段落和显式换行回读正文，忽略浏览器 `innerText` 为块级排版额外生成的空行；编辑器用于占位的末尾换行也不算正文。实际空段落、词间空格、文字、标点和话题仍参与核对，只有换行编码与普通空格/不换行空格做等价处理。真实文字丢失或段落变化仍会停止发布，不会跳过核对。

## 验证和不确定结果

遇到平台安全验证、滑块、账号异常或操作频繁提示，会停止操作，提示在官方客户端处理后重新连接。没有实现验证码绕过、浏览器指纹伪造、代理轮换或人工操作伪装，也不能保证平台不要求验证。

提交后网络中断、未知响应或服务重启会产生「结果待核实」，禁止该用户继续发布，防止重复笔记。请先到官方创作中心核实，再选择：

- 已发布：填写 `https://www.xiaohongshu.com/explore/笔记编号` 链接，标记并记录人工核实结果。
- 未发布：解除限制，下次点击会重新提交。若判断错误，可能重复发布。

任务进度会显示打开创作中心、切换图文、上传第几张图片、等待图片处理、填写标题和正文等阶段；失败记录保留具体环节，不再只显示笼统的页面加载错误。

当前没有可靠的远端自动核实接口，发布页提供人工核实。用户填写的链接表示人工声明，不能视作平台再次验证。

## 参考与验证范围

参考 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 的官方网页扫码登录、Cookie 持久化、创作中心图文上传流程与页面元素。使用当前项目的 Playwright 实现，没有引入其 humanize 模块。

检查包括服务层与浏览器驱动测试、类型检查、生产构建，以及隔离的浏览器 UI 模拟测试：

```bash
npm test
npm run typecheck
npm run build
node scripts/smoke-xiaohongshu-publish.mjs
node scripts/smoke-xiaohongshu-publish.mjs --long-cards
node scripts/smoke-xiaohongshu-driver.mjs
```

自动测试不会访问真实小红书或发布真实内容。另已在真实创作中心使用保存的会话验证页面加载、图文切换、连续上传两张图片及标题/正文回读，验证停在提交前。尚未执行真实发布，最终提交响应和平台审核仍需实际环境确认。
